# Content and Licensing

AJ's Character Manager separates software licensing from the licensing of
rules and user content. This document describes the project's intended policy;
it is not legal advice.

## Application code

Original application source code and repository documentation are released
under the [MIT License](../LICENSE), unless a file clearly states otherwise.
The MIT license does not automatically apply to rules text, artwork, example
settings, imported packs, or content created by users.

## SRD content

Material derived from the official System Reference Document 5.2.1 will retain
the attribution required by its Creative Commons Attribution 4.0 International
license. Distributions containing that material must also identify meaningful
transformations or corrections as appropriate. The current Phase 0 repository
does not contain an SRD catalog.

The project's independent and unofficial status must remain clear. It must not
use official logos, D&D Beyond branding, the stylized dragon ampersand,
Wizards logos, or copyrighted artwork without permission.

## Third-party structured data and transcriptions

A machine-readable dataset may contain both licensed software and separately
licensed rules content. Before using one, contributors must establish:

- the license and provenance of the relevant records;
- that the records actually represent SRD 5.2.1 rather than an older ruleset;
- what transformations or corrections the project makes; and
- which notices must accompany source files and distributions.

Third-party data should be pinned, reviewed against the official SRD, and
listed in [Third-Party Notices](../THIRD_PARTY_NOTICES.md). Convenience or
public availability is not evidence of redistribution permission.

## Example content packs

Each example pack needs its own explicit license and attribution. Its license
does not change the application's code license. Briarwood is planned as a
Phase 2 example only after its redistributable text and assets are identified.
The private Word source and its embedded artwork are not public project assets
and must not be committed or distributed.

## Imported and user-created content

Users retain responsibility for the rights to content they create or import.
The application should permit local use without representing that the content
may be published. Export should preserve known license and attribution data,
and sharing should be presented as appropriate only when the user has the
necessary rights.

Proprietary rules text and artwork should remain local unless the user has
clear redistribution permission. The project will not accept such material
into its public catalog simply because a user can import it privately.

AJ's Character Manager is an independent, unofficial project and is not
affiliated with or endorsed by Wizards of the Coast.
